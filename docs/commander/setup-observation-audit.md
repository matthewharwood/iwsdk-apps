# Setup observation audit and first-player choice

This bounded review uses the [pinned comprehensive rules](https://media.wizards.com/2026/downloads/MagicCompRules%2020260819.txt), SHA-256 `4381ad1b39ab2c05f7d03633a20f711ed37277074d3266dcba5f38cbb527423f`, effective August 7, 2026. The archived bytes are retained in `.commander/sources/archives`. These findings do not certify all of rule 103 or the setup scenario group.

## Public mulligan information: implemented and independently reviewed

CR 103.5 specifies declarations before the round's simultaneous mulligans: “Then each other player in turn order does the same.” A later player therefore knows earlier declarations when making their own choice. The engine collected them correctly in `setupChoices`, but `observe` omitted them. A client using only its entitled observation could not distinguish an earlier keep declaration from an earlier mulligan declaration.

The independent expectation is that every seat can see each pending declaration, the number of mulligans already taken, and which players have finished keeping. New hands, selected bottom-card identities and nonowned decision constraints remain private under CR 402.3. The declaration is not an early redraw: every player's existing hand stays unchanged until the round's declarations are complete. The first multiplayer mulligan counts in the public history while remaining free for bottoming under CR 103.5c.

`PlayerObservation.players` and `observe` now expose:

- `mulliganDeclaration`: `true` for keep, `false` for mulligan, or `null` when this round has no pending declaration for that player. Completing a declaration round clears its declarations.
- `mulligans`: actual redraws taken, including the first free multiplayer mulligan.
- `keptHand`: the player has completed keeping and cannot rejoin later rounds. During an unfinished round, their public keep declaration supplies the immediately visible choice.

The two tests in `packages/engine/src/audit-scenarios.test.ts` execute actual setup transitions for ordinary two-seat and four-seat games. Their exact names are `SET-04 2 seats see mulligan declarations and history while hands and bottom choices stay private` and the corresponding `4 seats` test. Both passed with 84 assertions in `.commander/evidence/setup-observation.junit.xml`. They cover declaration order/visibility, free versus paid counts, kept-player state, round reset, hidden hands and bottom choices, and detached observation values. Synthetic 100-card decks isolate this behavior; these are not source-card or whole-group certification. The earlier aggregate scenario map remains historical and does not silently inherit this run.

## First-player choice: implemented and independently reviewed in engine 0.6

CR 103.1 first determines the player who “will choose who takes the first turn.” The earlier engine used the seeded random result directly as the starting player, without providing that player's choice. A seeded method can select the chooser, and that chooser can choose themselves, but the core must also allow them to choose another seat. This omission is separate from the corrected mulligan projection.

The source-derived plan below was recorded before implementation. It was applied after the verified engine 0.5 checkpoint `db05a729`, as engine `commander-engine/0.6.0`:

1. Added a versioned `starting-player` decision owned by the chooser, with all manifest seats as its allowed `players`, and a matching response naming one seat. Chooser and selected starting player are explicit in durable setup state; the selected player, active player and priority player are initially `null`. The seed selects only the chooser at this stage.
2. Deferred commander placement, library shuffling and opening hands until that response commits. An explicit pre-deal setup state has a strict invariant: no live game objects, hands, stack or other decisions yet, while the validated manifest still owns every complete deck. After selection, the engine creates all 100 physical cards per seat, places every commander in command, shuffles every remaining 99-card library and then draws seven for each seat. The ordinary 100-object invariant still applies after selection.
3. Mulligan declarations begin at the selected starting player and continue clockwise in manifest seat order. The selection remains in history as the game advances. The existing two-seat first-draw skip and multiplayer first draw now follow the selected player. Pregame mulligans do not grant priority.
4. Heuristic `observed-combat/4` proposes choosing itself through the ordinary response boundary. Terminal `terminal-observation/2` displays the chooser and selection and accepts a JSON response override. Setup fixtures submit the extra decision explicitly; `createMatch` never chooses on behalf of a player.
5. The engine identity is `commander-engine/0.6.0`; existing contract and sorted-JSON serialization identifiers are unchanged. New required state fields and the engine pin deliberately reject older engine evidence under this executor. Older evidence needs its preserved executor, rather than reinterpreting its first mulligan command as a starting-player response.

The independent expectations recorded before implementation were: chooser selection is reproducible for one seed; no hand is available before choosing; the chooser may choose themselves or any other seat; wrong actor, stale decision and unknown seat leave state/RNG unchanged; the chosen seat owns the first mulligan declaration; all later declarations follow the rotated seat order; and first-draw behavior follows the chosen seat in both modes. Save, reopen and replay before and after the choice must preserve its owner and final selection. Relevant rules are 103.1, 101.4e, 103.2c, 103.3, 103.5 and 103.8a–c. The bounded implementation covers ordinary two-seat and four-seat single games, with the manifest seed as the agreed chooser-selection method. Match-series loser selection, shared-team variants, Archenemy and starting-player overrides remain outside this implementation.


The production run `.commander/evidence/setup-choice-0.6.junit.xml` passed 84 tests with 1,641 assertions across engine, heuristic and terminal suites. Within that run, `audit-scenarios.test.ts` passed all ten tests with 346 assertions: the two earlier public-mulligan tests plus eight new first-player-choice tests. The new cases exercise deterministic private pre-deal state and rejected commands in both seat modes, followed by each possible selected seat (two plus four), rotated mulligan declarations, all commanders before shuffling, all shuffles before drawing, real first-upkeep priority and the appropriate first draw. They also verify that missing card inventory after selection fails the invariant. The actual frozen CLI test accepts one initial choice, pauses, reopens and replays it. Contracts, engine and simulation type checks passed; Biome and Sonar checks passed for all sixteen changed source files. The separate [setup persistence proof](setup-browser-proof-0.6.md) now records 23 passing native SQLite tests with 285 assertions, including pending-choice faults, retries and import. Its real Chromium worker/OPFS run completed one two-seat and one four-seat game with 574 and 1,911 commands, preserving all 575 and 1,912 native/browser/import boundaries. Both games verified undealt reload/import, chooser-only observations, exactly one committed choice and idempotent post-deal retries. This evidence is separate from the 84-test run and does not establish physical headset behavior. No full rule-103 or setup-group completion is asserted.

Root independently reviewed the pinned setup rules and `setup`, `index`, `invariants` and heuristic code after implementation.
