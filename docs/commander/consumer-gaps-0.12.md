# Commander consumer gap audit

Read-only inspection, September 6, 2026, against `/private/tmp/iwsdk-commander-0.12`. No application, studio, engine, storage or test changes were made. The acceptance cases below are proposed work, not executed evidence.

**Conclusion:** the repository has a reusable desktop/XR token application, shared studio-derived card presentation, and a real Commander engine/storage worker proof. It does not yet have a playable or navigable-replay Commander application. Joining those pieces requires a production session boundary, authenticated content/display packaging, decision controls and a Commander scene; importing the proof worker or showing `/cards` would not complete that work.

## Scope and evidence boundaries

`docs/_temp/COMPLETE_SPEC.md:168–173` defines G6 as “Reproducible release and player-visible session contract are usable without learning implementation internals.” Its literal workstream is headless and explicitly excludes gameplay React/IWSDK/VR (`:33–37`, `:877`). Its consumer contract requires permitted observations, decisions and redacted events (`:237`, `:532–549`); persistence and replay requirements are at `:551–579`. Thus G6 is not itself a claim that a rendered game exists. The user's additional application/presentation request, recorded in `docs/commander/card-design-audit.md:3–5`, is a separate consumer deliverable; the older document's exclusion does not erase that request. This audit implements neither scope.

The inspected engine ABI is `commander-engine/0.12.0`. The candidate release `.draft-artifacts/release-fixed-token-v0.12.json` has hash `fd5d52dc3d11284940cae72faace2ca0ead11deaa11508c12ea6b179967912a4`: 1,129 primary definitions and 20 auxiliary token templates, explicitly `development-subset`. Its 40-deck artifact preserves 35 earlier decks and adds five; 26 of 27 bound token producers have compatible legal fixture decks, while Call to the Feast lacks an admitted white/black commander. These are bounded content facts, not G5 completion or a claim that every rendered card can execute. This audit does not qualify the concurrently running 0.12 proofs.

## Contract gaps to close before wiring presentation

1. **Bound-player worker protocol.** Add a Commander-specific request/response schema and session facade. A UI supplies a `Response` against the exact `matchId`, `revision`, `decisionId` and actor, but the worker binds the allowed human seat rather than trusting an arbitrary posted actor. Use `Coordinator.view(boundSeat)`, never `current()` or archive snapshots as a UI model. `PlayerObservation` currently has a TypeScript type, not a complete runtime response schema. Validate/version messages, stale responses and error codes at the boundary. The existing `SubmitResult` distinguishes rejected, unsupported and fault; preserve those distinctions rather than displaying a false game loss/draw.

2. **Public context and events.** `packages/engine/src/index.ts:182` hides libraries and other players' hands and returns the owned decision only. Preserve that projection. It does not expose the public priority player/pending chooser to a nonacting seat, authoritative graveyard order, or player poison/loss-reason fields. `objects` is sorted by object ID, so it cannot stand in for an ordered graveyard. Add only the necessary public fields through the engine contract; do not fetch full `PlayerState` into React to fill them. `GameEvent.visibility` exists, but no exported production redacted event feed does. Project `public` plus the bound seat's events, exclude `judge`, and review event payloads/errors for indirect leaks. Public decision context must not include another seat's private candidate list. Existing observations also contain implementation programs/obligations; the app should render game facts, not dump those internals.

3. **Content and compatibility.** A source release, deck choices, compiled programs and exact display facts are absent from `apps/web/public` and the app build. The proof reads local ignored `.commander` artifacts. Package a declared immutable release and versioned deck manifest as build inputs, preserving their hashes/assurance and source provenance. Use browser-pure `@iwsdk-apps/compiler/prepared`; the compiler root also imports the Bun catalog and is unsuitable for a browser worker. `Coordinator.create/open` validates source/decks and prepared closure, and the full/prepared factories now require the current processor ABI. A self-consistent arbitrary release hash is not authentication. Do not promote all source candidates to selectable decks or silently upgrade a saved match to new engine/content bytes.

4. **Display facts versus execution facts.** `CardDefinition` retains exact `oracleText` and type line, but mana cost is normalized `Cost` counts, P/T are numeric/null, and layout/faces/color indicators/printing rarity are absent. For exact studio-style source display, generate a release-associated, source-version-bound `CardDisplay` map from authenticated catalog facts; do not recover missing original mana ordering or future faces by guessing. The current bounded single-face subset can initially use an explicitly documented adapter, omitting unknown printing rarity. Keep `characteristics.power/toughness/keywords`, counters, damage, tapped state and changed controller in live overlays, distinct from printed facts. `HiddenCard` must receive no identity; surrounding keys, ARIA labels, textures and ordering must also remain private.

5. **Token and stack identities.** `PlayerObservation.objects` is a union: a real card has `card:CardDefinition`, while a token has `card:null, tokenTemplate:TokenTemplate`. Render a token from the template's typed characteristics, mark it as a token, use null mana cost/no rarity and separate per-object state. Never look up an auxiliary template in primary definitions or count it as a deck card. Different token objects sharing a template still have distinct IDs/lineages. Reconcile token disappearance and generation changes from committed observations. Stack entries separately identify spells and triggered abilities; an ability inspector uses `abilities.sourceCard` and captured controller/source context, including after the source leaves play. It must not assume every stack entry is a live card object.

6. **Durable interaction and playback.** Keep the entire submitted command envelope when awaiting or retrying a receipt. Do not recreate its revision or decision ID after a timeout. Define recovery for an unknown reply after worker/page restart, retaining pending request identity or querying its durable receipt; the token session's in-memory retry map alone does not survive reload. Export the logical archive as a backup with a clear privacy notice: it contains privileged saved state, unlike a public replay view. Import remains bounded (currently 64 MiB), verifies every pin and history, preserves existing saves on failure and explicitly handles duplicate identity. Add an observation-based replay-at-boundary/seek API that verifies the archive, replays accepted commands with the pinned registry, and never mutates the live match or applies commands and events twice. Old ABI saves currently reject; provide an explicit compatible-build/open path or an understandable incompatibility state rather than pretending migration exists.

## Concrete implementation order

The following paths are proposed additions unless already listed above. Keep the studio as an unchanged reference and keep the generic starter adapter separable from Commander.

1. **Package a reproducible browser release.** Add `apps/web/scripts/sync-commander-content.ts` with explicit input release/decks/display manifest and integrity checks; produce only replaceable build assets. Wire app dependencies/build scripts and `scripts/build-offline.ts`. Use `import.meta.env.BASE_URL` for worker/WASM/content paths instead of the proof's root-only URLs. Ensure offline assets include the exact release/worker pair, local card fonts/symbols and XR controller assets. Account for download/cache/memory cost; the existing service worker deletes older asset caches on activation, so it does not by itself retain old replay engines/releases.

2. **Provide the production session.** Add `app/game/session/commander-protocol.ts`, `commander-session.ts`, and `app/game/workers/commander.worker.ts`; wrap `openBrowserRepository`, `Repository.list`, `Coordinator` and logical save APIs. Extend pure contracts for the reviewed public projection/event envelope; add a storage replay cursor API. Reuse the existing lifecycle/request discipline, but keep token and Commander namespaces/protocols separate. Permit role metadata for one human plus observation-only deterministic opponents without passing another seat's view to the human UI. Do not reuse the proof's arbitrary actor/run/evidence endpoints.

3. **Build the actual route and decision surface.** Add a `routes/commander.tsx` lobby/parent, `routes/commander.$matchId.tsx` live route and a replay child route; use a session-scoped Jotai provider and committed snapshots. A new `ui/commander-workspace.tsx` should expose seat/deck selection, saved games, public players/zones, owned hand, stack/ability inspection, phase/priority, action status and backups. `ui/commander-decision.tsx` must handle every current decision: starting-player, mulligan, bottom, priority, target, payment/cancel, attack, block, damage, trigger-order, commander-zone, commander-replacement and discard. Candidate IDs, costs and damage constraints come from `Decision`; selection drafts are disposable UI state. Domain validation stays in the worker. Unknown future decisions pause visibly.

4. **Share the studio design in actual play.** Add `game/presentation/commander-display.ts` for permitted observed card/token/ability display models. Use `@iwsdk-apps/card-design/react` for the full inspector and shared design tokens for compact hand/table views and shell typography. Put live interaction outlines and current-state badges in app chrome; do not reuse decorative timeline annotations as actual timing legality. Preserve complete rules on inspection and explicit face composition. No duplicated renderer from the studio, rewritten Oracle text, inferred annotation semantics or engine dependency on React/card-design.

5. **Implement the Commander spatial consumer.** Add `game/scene/commander-table.ts` consuming the same presentation/session model and command adapter. Use shared fonts/symbols/tokens with a tested spatial card/text implementation; CSS/React layout is not automatically present inside WebXR. Provide legible inspect, select, confirm/cancel, pass, payment, combat, ordering and owner-choice panels in-world, plus replay controls and exit. Card dragging, if added, is only an intent followed by an ordinary command, never a local zone mutation. Keep owned resource disposal, session exit/re-entry and stale revision handling from the starter. Store no independent scene rules state.

## Proposed acceptance cases, not yet executed

| Case | Required evidence |
| --- | --- |
| Reproducible app handoff | Fresh checkout plus documented build inputs produces a served Commander route with verified source/deck/display pins. A user can start/resume a two- or four-seat game without CLI JSON, SQL or implementation IDs. Unimplemented cards/decks are explained before play, with development assurance visible. |
| Complete human command surface | Drive actual route controls through ordinary setup, meaningful casting/combat/effects and completion for two/four seats; retain commands and compare native replay boundaries. Exercise all current decision kinds, including owner-controlled commander replacement and trigger ordering. No fixture injection into qualifying complete games. |
| Visibility | Bound-seat worker messages, DOM/ARIA, card textures and logs contain no other hand/library identities. An inactive player sees public pending actor/status but no private decision candidates. Changing the view is an explicit seat handoff; closing an inspector/seat change clears prior private resources. |
| Recovery and ownership | Reload during starting choice, target/payment, trigger order and paused commander return; restore the same decision. Retry the exact accepted envelope before/after reopen/import returns the original receipt and no state change; changed payload conflicts. Second-tab lock, crashed worker, unavailable/quota-failed OPFS and route remount preserve the last committed save. |
| Save and replay | Bounded valid import, corrupted checksum/history, wrong release/ABI, duplicate match and interrupted import preserve existing saves. Replay can seek forward/backward and inspect permitted observations without submitting live commands; end state matches verified replay. Backup export and player-visible replay have distinct privacy semantics. |
| Shared design and tokens | Authenticated card text, mana, fonts, symbols and all supplied faces render without SSR hydration mismatches or clipped rules. Current stats remain distinct from printed stats. Actual token creation shows separate objects with all supported template traits; return/destruction removes them at the committed rules boundary. Noncard stack abilities remain inspectable after source departure. |
| Actual XR consumer | Emulated controller rays operate Commander decisions through the same worker as desktop and preserve the game across in-world exit/re-entry. Essential choices are operable without inaccessible HTML overlays. Test first XR entry offline with content/fonts/controllers cached and a subpath deployment. Existing TAKE tests do not satisfy this case. |
| Device qualification | Physical Quest testing must separately establish seated text readability, target reach, controller/hand input, interruption/re-entry, device OPFS durability and sustained frame-time/memory/load budgets with real Commander object counts. No physical headset qualification is currently recorded in `docs/validation.md` or `docs/quest.md`. |

Existing evidence remains valid within its recorded scope: token application tests, card-design/route presentation tests, terminal tests and Commander native/browser-worker parity. None is being relabeled as a completed Commander React/WebXR consumer or full-snapshot semantic release.
