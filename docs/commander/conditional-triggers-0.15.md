CR 603.4 and 608.2a require two different checks. False at entry means no triggered ability exists. Becoming true later cannot create that missed occurrence. If an ability was created, a false condition at resolution removes it from the stack without effects. This is ordinary rules processing, not a counter operation or a rejected player command. Donatello's retained ruling confirms both checks.

The new strict program variant admits only current battlefield Artifact existence controlled by the captured trigger controller, followed by drawing one card. All three resolver paths query current objects at each check. They do not retain an artifact witness or use the earlier Boolean result as authority. Source removal or a later source-controller change does not rebind “you”; a different current artifact can satisfy the second check. No additional check occurs while placing the waiting ability on the stack. This is a bounded intervening-if implementation: history predicates, thresholds, opponents, attachments, copies and arbitrary conditional expressions remain unsupported.

The core emits distinct condition-evaluation and false-removal evidence. Stored program/controller/source context is validated before command dispatch, including before a resolution could erase that evidence. False resolution produces no draw, normal-resolution event or spell-counter event. A true failed draw finishes the ability before the usual state-based loss check. Existing unconditional self-entry and entry-observer definitions retain their prior representation and behavior.
